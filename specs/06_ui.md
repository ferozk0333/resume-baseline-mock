# 06 — UI (Streamlit)

Simple, functional, local. Brand name **RightStaff**. Four pages plus a collapsible weights sidebar available on the Score and Gaps pages.

Run: `.venv/bin/streamlit run app/Home.py`. Implementation notes (phase 7):
- One `Pipeline` per browser session holds the paused review state; if it is lost (app restart), "Confirm & score" scores the saved profile directly.
- Re-running extraction reuses the same candidate: old evidence and dropped items are cleared and the profile is replaced (after the confirmation checkbox). Unchanged text keeps its saved judgments (they are keyed by input).
- Review edits: roles/projects are edited in place (bullets one per line; unchanged bullets keep their id and judgments); "Outcomes" is a read-only view of bullets that state a number (outcomes are not a separate extracted type).
- Baselines form: level and required years sit outside the form so the level/years warning updates as you type.
- Progress: each finished step is written to a status box ("Expertise › Role-specific skills done").
- **Live pipeline view (demo):** during extraction and scoring a Graphviz diagram of the LangGraph pipeline updates from LangGraph task events: onboarding chain on top, one column per dimension with its subcategories, aggregate → plan at the bottom. Colours: amber running (with the step: judging / computing / saving), green done, orange missing evidence, grey N/A or waiting, red error, blue waiting for review, dashed skipped (e.g. onboarding steps on a re-score). The last run's picture stays in an expander; Home shows the structure.
- Tests: `tests/test_ui.py` runs every page headless (Streamlit AppTest) with fake deps via `RIGHTSTAFF_DEPS_FACTORY=tests.ui_fakes:make_deps`.

## Home
- Short explanation of what the mock does.
- Pick a candidate (or "New candidate") and a baseline.
- Buttons: Start onboarding · View latest score.
- Past runs list: runs whose baseline was deleted still display, with the baseline shown as "(deleted)".

## 1. Baselines
- List baselines (title, level, required years, # required / # preferred items, "mock" badge).
- Create / edit form:
  - title, level, required_years, expected_reach (1–5 with labels: own work, team, cross-functional, organization, external)
  - scope_expectation (text), complexity_criteria (text), description (short JD)
  - criteria table (editable rows): kind (skill/tool/certification), name, description, aliases (comma-separated), priority (required/preferred)
  - Warning (non-blocking) when level and required_years disagree: `entry` with > 2 years, or any other level with ≤ 2 years. Scoring uses required_years only (see `04` §1).
- Delete with confirmation.
- "Reset seed baselines" button reloads `seed/baselines.json`.

## 2. Onboarding
**Step 1 — Inputs**
- Resume upload (PDF/DOCX, required)
- LinkedIn profile PDF (optional) with help text: "On LinkedIn, open your profile → More → Save to PDF."
- GitHub username or URL (optional)
- Portfolio URL (optional)
- Certifications (repeatable: name, issuer, date, credential ID, verify URL)
- References (repeatable: name, relationship [manager/supervisor/peer/other], contact, short statement)
- Button: Extract

**Step 2 — Review (Tsenta-style prefill)**
- Show extracted data as editable sections: Roles (with bullets), Projects, Skills & tools, Outcomes, Certifications.
- Highlight items with `needs_review` (missing end date, future date, unparsed date).
- Show the source quote under each item (collapsed).
- Add / edit / delete rows. Edited rows saved with `source = user_edit`.
- Show ingest warnings (e.g. "Portfolio returned no text — add projects manually", "GitHub rate limit").
- **Dropped items:** list every item the quote check dropped (type, text, source document) with an **Add back** button. An added-back item is saved with `source = user_edit`. A bullet whose role/project was also dropped can be added back only after its parent.
- **Re-running extraction** replaces the saved profile, including review edits and added-back items. Show a confirmation warning before a re-run.
- Button: Confirm & score (disabled until at least one role or project exists).

## 3. Score
- Header: final score (0–100) and the four dimension scores. No "strong/weak" labels.
- Progress indicator while the graph runs (per dimension).
- For each dimension: a table of subcategories with score, status badge (scored / missing / N/A / error) and weight.
- Expand a subcategory to see: the formula used, the per-item breakdown (e.g. per skill: bullet/keyword/missing), and the judgments with quote, label, probabilities and method (jev/claude/rule).
- Jev judgments have no quote: show the judged bullet/role/project text as the evidence, labelled "judged text; Jev returns no quote". Show Jev confidence, and for Claude judgments that replaced a low-confidence Jev answer, show both.
- `missing` rows show their guidance message.
- Judgments marked not used (a low-confidence Jev answer, kept even when the Claude fallback also failed) are shown under the used one, labelled "Jev (not used: below confidence threshold)".
- **Re-judge (clear saved judgments)** button *(proposal)*: marks this candidate's saved judgments for the selected baseline as not used (`judges.service.clear_judgments`) and re-runs scoring, so judgments are asked again. Rows are kept (append-only). Without it, re-scoring always reuses saved judgments.
- Complexity shows a small note: "Graded by a reasoning model; can vary slightly between fresh runs." (see `05`, Sampling and determinism).

## 4. Gaps
- Ranked gap list from code (subcategory, status, current score, "up to N points").
- **Improvement plan as action cards**, ordered by points: type, title, what to do, what it must show, gaps addressed, skills/tools covered, builds on, and "up to N points if fully closed". Below the cards: quick wins, then "Not closable by a near-term action". Show dropped actions (and errors fixed by the retry) in a collapsed "Validation notes" expander.
- Slider changes re-price and re-order the stored plan instantly, with no model call.
- Button: **Regenerate plan** (calls the model with the current weights).

## Weights sidebar (Score and Gaps pages)
- `st.sidebar` with an expander **"Weights (experiment)"**, collapsed by default.
- Section "Dimensions": 4 sliders (0–100, whole numbers, step 1). Shows normalized % next to each.
- One sub-expander per dimension with sliders for its subcategories (0–100, whole numbers, step 1), normalized within the dimension.
- Defaults = table in `04` §6. Trust sliders start at 30 / 30 / 25 / 10, which normalize to exactly the redistributed 31.58% / 31.58% / 26.32% / 10.53% (same scores).
- Changing any slider re-runs `scoring/aggregate.py` on saved subcategory scores and re-ranks gaps instantly. **No model calls.**
- Buttons: "Reset to table" · "Save weights to this run" (writes `runs.weights_json`).
- Show a small note when a subcategory is N/A: its weight is redistributed.

## Behaviour
- Long-running steps show a spinner and log lines (e.g. "Judging relevance: 4 roles, 3 projects").
- Errors are shown inline, never as a stack trace (stack traces go to the console log).
